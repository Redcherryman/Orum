# Orum v0.006 — freestanding target

The last kernel blocker (after v0.004's volatile raw pointers and v0.005's
inline `asm`). `--freestanding` compiles Orum for bare metal: no syscalls,
no `brk` heap, configurable entry symbol, real ELF sections carrying the
extern heap symbols and relocations.

```
orumc kernel.orum -o kernel --freestanding --entry kmain
```

Driver API: `compile_source(src, freestanding=False, entry="_start")`,
`build_binary(src, path, freestanding=False, entry="_start")`.

## What freestanding changes

**No syscalls, ever.** The final binary is scanned in tests for `0F 05`
bytes — there are none. Any missed syscall site is a loud compile error
(`emit_syscall` raises in freestanding mode), not a silent violation.

**`say` / `exit` are compile errors.** Both need syscalls, so the
typechecker rejects them: `'say' requires hosted mode — it needs
syscalls`. Hosted mode is unchanged.

**`crash` halts the CPU.** No stderr to write to, so `crash "msg"` emits
`cli; hlt; jmp hlt`. The message is still typechecked but not evaluated.
`__die` (out-of-memory, index-out-of-bounds) does the same — on bare
metal there is no graceful fatal exit, only a stopped CPU.

**Entry never returns.** After the entry file's top-level statements run
(Orum's rule — the file is the program — holds on bare metal), the entry
falls through to `cli; hlt; jmp hlt` instead of `exit(0)`.

**Entry symbol is configurable** (`--entry`, default `_start`). It is
recorded in `.symtab` as a GLOBAL FUNC SHN_ABS symbol whose value equals
the ELF header's `e_entry`, so `readelf -s` can verify the entry point.

## The heap contract (what the kernel must provide)

The bump allocator is driven by two extern symbols instead of `brk`:

- `__orum_heap_start` — address of the first usable heap byte
- `__orum_heap_end` — address one past the last usable heap byte

Both must be **8-aligned**. At entry, generated code loads them into
Orum's heap slots (`heap_ptr`, `heap_end`) via `R_X86_64_64`
relocations. They appear in `.symtab` as GLOBAL NOTYPE UND symbols;
`.rela.text` carries one relocation per symbol.

**Link step required.** The emitted binary's relocation placeholders are
zero — it must be linked (resolving the two symbols, e.g. from a linker
script: `__orum_heap_start = ORIGIN(heap);`) before it can boot. This is
documented, not hidden: an unlinked freestanding binary will fault if its
heap is used.

## ELF layout (freestanding only)

Hosted output is byte-identical to v0.005 (no sections). Freestanding
appends, after `.data`:

- `.symtab` — null, `__orum_heap_start` (UND), `__orum_heap_end`
  (UND), entry symbol (SHN_ABS = e_entry)
- `.strtab`, `.shstrtab`
- `.rela.text` — `R_X86_64_64` entries at the vaddr of each recorded
  `movabs` immediate, against the UND symbols

Section headers are filled in (`e_shoff`, `e_shnum` = 5, `e_shstrndx`).

## Not supported / not attempted

- UEFI/PE output, multiboot headers, flat binaries — out of scope.
- QEMU boot smoke test: QEMU is not installed on this machine;
  documented here, not attempted (nothing was installed).
- `crash` in freestanding is unverifiable on Linux (it halts) —
  verified structurally (`FA F4` bytes present, zero syscalls).
- Privileged instructions in `asm` (`in`/`out` port I/O, `cli`,
  `hlt`, CR access) still fault in userspace; they are for
  freestanding/kernel use.

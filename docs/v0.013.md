# Orum v0.013 — complete compilation workflow

Orum now supports true separate compilation: compile source files into relocatable `.o` object files, then link those objects into a runnable ELF executable.

## Compile and link

```sh
python3 -m orum.orumc -c main.orum -o main.o
python3 -m orum.orumc -c helper.orum -o helper.o
python3 -m orum.orumc --link main.o helper.o -o program
./program
```

`-c` compiles one Orum source file to an object file. The default output name replaces `.orum` with `.o`. `--link` accepts one or more Orum object files and produces an executable (default `a.out`). Use `-o` to select either output path. The compiler refuses to overwrite an input file.

Object files contain code, read-only and writable data, symbols and relocations. Function definitions are exported; calls to functions defined in other objects remain unresolved until linking. The linker resolves symbols, combines and relocates section data, and emits the executable. Undefined symbols, duplicate definitions and unsupported relocation types are reported as errors.

## Freestanding builds

Add `--freestanding` to compile and link for a kernel or other bare-metal target. The default ELF entry symbol is `_start`; select another with `--entry SYMBOL`:

```sh
python3 -m orum.orumc -c kernel.orum -o kernel.o --freestanding
python3 -m orum.orumc --link kernel.o -o kernel.elf --freestanding --entry kmain
```

Freestanding objects reference the undefined linker symbols `__orum_heap_start` and `__orum_heap_end` when the heap is used. Define both symbols in the final link environment; they must delimit the available heap and be 8-byte aligned. Freestanding mode does not emit syscalls: `say` and `exit` are rejected, and `crash` halts the CPU.

## Module imports

`take` and `share` module imports continue to work in direct compilation. Module paths are resolved relative to the importing source file, including nested imports. Cyclic imports are rejected. For example, `examples/use_circle.orum` imports the shared value from `examples/math/circle.orum`.

## Compatibility

The object reader continues to accept version 1 object files. Hosted direct compilation behavior is retained. Run the test suite from the repository root with:

```sh
python3 -m unittest discover -s tests
```

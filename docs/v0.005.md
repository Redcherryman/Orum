# Orum v0.005 — inline `asm` blocks

The kernel blocker #2 (after v0.004's volatile raw pointers). Statement-level
`asm ... end` blocks inside `fn` bodies (top-level works too — same frame
machinery).

## Syntax

```
asm
in <var> = <reg>        # copy Orum integer variable into register (before)
out <var> = <reg>       # copy register into a `mut` Orum variable (after)
clobber "<reg>"         # declared-trashed register
raw <byte>, <byte>, ... # machine-code bytes, emitted verbatim
end
```

Directives may appear in any source order and may repeat. `raw` lines may
repeat; bytes accumulate.

## Emission order

ALWAYS: **in-moves → raw bytes → out-moves**, regardless of source order.
The block may trash any register except rsp/rbp; Orum values cross the
boundary only through declared `in`/`out`. At statement level no Orum value
is live in a register, so this is sound.

## Registers

Allowed: `rax rbx rcx rdx rsi rdi r8`–`r15`, plus 32-bit aliases
`eax ebx ecx edx esi edi r8d`–`r15d`.

- 64-bit names move the full word.
- 32-bit names move the low 32 bits: `in x = eax` loads 32 bits
  (zero-extended); `out y = eax` zero-extends into the 64-bit slot.
- `rsp rbp esp ebp` are compile errors — the compiler owns the frame.
- Unknown names are compile errors.

## Type rules (all compile errors, never silent)

- `in` var: must be a declared integer-typed variable (locals and params).
- `out` var: must be a declared **mut** integer variable — it's a write,
  so the `mut` rule applies. Writing to an immutable is an error.
- `raw` bytes: each must be 0–255 (parser rejects the rest).
- `clobber` names must be known, non-frame registers.

## The honest no-assembler design

Orum's pipeline (lexer → parser → typecheck → x86-64 codegen → ELF) contains
no assembler and v0.005 adds none. `raw` bytes are emitted VERBATIM into the
text section — the programmer (or future intrinsics) supplies exact machine
code, e.g. `raw 0x0F, 0x31` is `rdtsc`. This is deliberate: a from-scratch
language with a direct-to-machine-code backend has no assembler to lean on,
so the escape hatch is explicit bytes, not pretend assembly.

## What is NOT verified

`clobber` declarations are **trusted, not verified**. Proving that raw bytes
only trash the declared registers requires decoding x86-64 instructions —
a real disassembler in the compiler. That's future work (documented, not
pretended). Undeclared clobbers are the programmer's bug; the compiler will
not catch them in v0.005.

## Privileged instructions

`in`/`out` port I/O, `cli`/`sti`, `hlt`, CR-register access and friends need
privilege (ring 0) — they will fault in userspace. They are for freestanding
kernel use (v0.006 target), NOT for hosted test programs. The v0.005 test
suite only exercises unprivileged instructions (`rdtsc`, `cpuid`, `nop`).

## Example

```orum
fn rdtsc() -> u64
mut lo: u64 = 0
mut hi: u64 = 0
asm
out lo = eax
out hi = edx
raw 0x0F, 0x31
end
return (hi << 32) | lo
end
```
